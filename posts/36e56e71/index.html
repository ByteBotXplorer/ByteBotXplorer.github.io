local map

local map（局部地图） 是围绕当前传感器 / 机器人位姿（pose）维护的小型环境地图子集，是全局地图的一个「局部切片」。

作用：

  • 用于scan-to-map配准（如激光点云与局部地图匹配，来估计当前位姿）

  • 支撑 局部BA（光束平差法）优化、局部位姿平滑

  • 避免全局地图的海量数据干扰，保证实时性与计算效率

和全局地图（global map）的区别：

  • 全局地图：记录完整环境的所有历史观测，用于长期定位、回环检测、最终建图结果
  • 局部地图：只保留当前 pose 附近的关键特征，专注于短期、局部的位姿估计与建图

控制范围

1. 空间范围限制（最直观）

以当前 pose 为中心，定义一个几何边界，只保留边界内的点：

  • 激光 SLAM（如 LIO-SAM、LeGO-LOAM）：

    • 常用：半径 20~50 米的球体，或 50m×50m×10m 的长方体（水平范围大、垂直范围小，适配地面机器人）
    • 超出边界的点会被直接从 local map 中移除，防止地图无限膨胀

  • 视觉 SLAM（如 VINS-Mono）：

    • 通常限制特征点深度在 0.5~50 米 之间，只保留当前帧可见且深度合理的点

2. 时间 / 关键帧窗口限制

不直接按空间，而是按观测时间或关键帧数量来维护：

  • 维护最近 N 个关键帧（比如 10~30 帧）的所有特征点，不管它们的空间位置
  • 或维护最近 T 秒（比如 10 秒）内传感器观测生成的地图点，适合动态场景快速更新

3. 稀疏性控制（额外约束）

即使在范围内，也会通过以下方式控制点数，避免过于密集：

  • 下采样：用体素网格（voxel grid）过滤，每个体素只保留 1 个点（分辨率常为 0.1m~0.2m）
  • 特征提取：只保留显著特征（如激光的角点 / 平面点、视觉的角点 / 边缘点），丢弃冗余点
  • 冗余剔除：重复观测的近点只保留 1 个，避免同一位置被多次观测导致点数爆炸

数据结构

树形结构

逻辑上的层级父子结构，核心：递归分层、自上而下索引。

八叉树、KD-Tree、四叉树……

特点：必须维护「父节点 - 子节点」的层级关系，哪怕空间是空的，也要保留节点来维持树的结构。

空间类型数据结构

是直接映射到物理空间位置的结构，不依赖层级树，直接通过「坐标 -> 存储位置」寻址。

二维栅格、三维体素、空间哈希表……

八叉树

即是空间数据结构、又是树形结构

「空体素不分割」是理论八叉树，但工程 / SLAM 中用的八叉树（如 OctoMap）需要分割每个非叶子节点。

  1. 八叉树必须维持树形结构

    根节点会强制分割为 8 个子节点，哪怕 7 个都是空气（空体素），也必须创建节点、标记为空，否则树的结构就断了，无法查询。

  2. 空叶子节点依然占用内存

    这些空体素节点要存储：坐标、层级、是否为空的标记，纯开销，没有任何点云数据。

增量式体素结构 iVox

iVox = 哈希表 + 伪希尔伯特空间填充曲线

哈希表

哈希表（Hash Table）是一种抽象的“表”结构，本质是 ** 哈希函数（Hash Function） + 底层数据结构（maybe数组）

哈希函数负责根据输入的 key 计算出一个 index（or hash index），数组负责在 index 的位置上保存 value 信息，共同构成了哈希表中的一条数据。

新增数据时，给定，根据 key 计算索引并在索引位置保存对应 value；

查找数据时，给定 key，通过 key 计算索引并返回索引位置的 value。

无论是新增还是查找，由于索引值是直接通过哈希函数对 key 计算出来的，因此复杂度始终是O(1)，与存储数据的规模无关，所以哈希表是一种比较高效的数据结构，且规模越大优势越明显。

C++ 标准库中的std::unordered_map是一种典型的类型容器，其内部正是封装了哈希表（ iVox 中的哈希表实现就是用的std::unordered_map）。

ivox的空间哈希函数

  • key：以体素的空间坐标 $v$ （整数坐标，= 物理坐标 * 体素边长）

  • 函数：对 $v$ 的三个维度各乘以一个很大的整数后，做异或位运算，得到的结果对哈希表的容量 $N$ 取余，得到 体素的 index——$id_v$

哈希冲突

在 iVox 中，算法只维护有限数量的体素，因此哈希表的负载因子（Load factor, 表示数据的规模占数组容量的比例）始终很小，再加上空间哈希函数在设计上也具备抗碰撞能力，因此 iVox 的碰撞概率应该是可以忽略不计的。

伪希尔伯特曲线（Perseudo Hillbert Curve, PHC）

希尔伯特曲线

希尔伯特空间填充曲线（Hilbert space-filling curve, or Hilbert curve），是空间填充曲线的一种。

基本原理

将空间分成一个个小单元，然后将这些单元的中心点用一条分段曲线（折线）连接起来，曲线是一维的（分段曲线拉直就是一维的，一根线只有「长度」这一维度，所以是一维的），但被其连接的各个单元是位于高维空间的，所以，该曲线就具有讲高维空间的元素映射到一维空间的能力，因此，可以据此在一维空间中来索引高维空间的存在。

希尔伯特曲线的「阶」直接定义了空间被分割成的小单元数量

二维空间

二维空间中，

一阶希尔伯特曲线把空间划分为 $2^1 * 2^1$ 个小单元，并按特定的走位规则把4个单元的中心点连接起来；

二阶希尔伯特曲线把空间划分为 $2^2 * 2^2$ 个小单元，并按特定的走位规则把16个单元的中心点连接起来；

三阶希尔伯特曲线把空间划分为 $2^3 * 2^3$ 个单元，并按特定的走位规则把64个单元的中心点连接起来；… …

N阶希尔伯特曲线把空间划分为 $2^N * 2^N$ 个单元，并按特定的走位规则把所有单元的中心点连接起来。

三维空间

N 阶曲线将空间划分为 $2^N 2^N 2^N$ 个小单元。

性质

  • 「阶数」越高，单元数量呈指数级增长，空间细分越精细，希尔伯特曲线越逼近于把整个空间完全填满；事实上数学上可以证明，在极限情况下，希尔伯特曲线是能够把空间完全填满的
  • 「走位规则」在希尔伯特曲线中是被明确和充分定义的，这个规则决定了高维索引与一维索引之间的映射函数长什么样子
  • 希尔伯特曲线具有「保持近邻关系」的能力，也就说如果两个元素在高维空间中是邻近的，那么它们在希尔伯特曲线上也是基本邻近的

伪希尔伯特曲线（PHC）

「伪希尔伯特曲线」指的是特定阶的希尔伯特曲线，它不能真正地填充整个空间，但阶数较高时可以做到近似填充。

「真正的希尔伯特曲线」是一系列伪希尔伯特曲线的极限，可以真正地填充整个空间。（引自知乎博主Neal）

iVox - PHC

iVox 是 Faster-LIO 用来管理 local map 的增量体素结构，PHC是它的索引核心：

  1. 大体素Voxel

    • 物理尺寸 $l_v$ （如0.2m），是local map的粗粒度空间划分
    • 只有包含点云的体素才会被创建

  2. 子空间单元

    • 每个大体素内部，再细分为$（2^K)^3$ 个更小的立方体单元，$K$的取值和体素大小相关

    • 每个小单元只维护内部所有点的质心，不是存储原始点

高维 <—> 一维映射

  • 正向映射 \H(t)=x**：
    • 输入：一维索引 t（PHC 曲线上的位置）
    • 输出：对应的三维小单元坐标 x
    • 本质：根据「走位规则」，从一维顺序还原三维空间位置（论文里没给具体实现，核心是快速位运算 / 查表）。
  • 逆向映射 \H−1(x)=t**：
    • 输入：三维小单元坐标 x
    • 输出：该单元在 PHC 上的一维索引 t
    • 这是 kNN 搜索的入口：把三维查询点所在的小单元，转成一维位置，后续在一维上找邻居。

KNN搜索

传统KNN搜索

暴力穷举（Brute-force）

原理：对每一个查询点，和地图里所有点挨个算距离，然后排序，选出最近的 k 个。

步骤：

  1. 有一个查询点 p（当前激光帧的一个点）
  2. 遍历 local map 里每一个地图点 m_i
  3. 计算欧氏距离：d = ||p - m_i||
  4. 把所有距离存起来，从小到大排序
  5. 取前 k 个距离最小的点，就是 k 近邻

复杂度：O(N) 每查一个点，N 是地图总点数

树形索引搜索（KD-Tree/ikd-Tree/八叉树）（工程）

FAST-LIO2 用 ikd-Tree，LIO-SAM 用 KD-Tree

KDTree 核心思想：把高维空间划分为多个子空间，搜索只在目标子空间内查找。

KDTree 构建：

  1. 选择一个维度 x 轴作为分割轴，找到该维度的中位数点作为分割节点；以分割节点为界，将所有点划分为「左子空间（x <中位数）」和「右子空间（x> 中位数）」；
  2. 对左右子空间，选择第二个维度 y 轴作为分割轴，进行第一步操作；
  3. 选择第三个维度 z 轴；
  4. 循环交替三个维度；
  5. 直到每个叶子节点只剩少量点，最终形成层级空间划分的二叉树。

KDTree 搜索：

  1. 快速定位目标子空间：从根节点出发，根据查询点的维度值（如 x 坐标），逐层向下比较，找到查询点所在的叶子节点；
  2. 初步找最近邻：计算该叶子节点内所有点与查询点的距离，记录当前最近邻；

  3. 剪枝回溯：向上回溯到父节点，判断「另一子空间是否可能存在更近的点」（通过比较「查询点到分割面的距离」和「当前最近邻距离」）：

    • 如果不可能，直接跳过该子空间（剪枝）；
    • 如果可能，进入该子空间重复搜索流程。

  4. 不断剪枝，最终得到全局最近邻。

KDTree 计算复杂度：

  • 构建树： O(N log N)
  • 单次查询：O(log N)

ikdTree是 FAST-LIO 团队优化的增量式 KDTree，适配激光 SLAM 的「动态增删点」场景：

  1. 增量式更新，而非重建传统 KDTree 是「静态」的，新增 / 删除点需要重建整棵树（时间复杂度 O(NlogN)）；ikd-Tree 支持增量增删：新增点时，直接插入到对应的子空间并调整树结构；删除点时，标记节点状态而非立即重构，仅在树失衡时局部调整。
  2. 结合局部地图的范围约束在 lasermap_fov_segment() 函数中，FAST-LIO 会根据当前位姿维护一个局部立方体空间（参数 cube_len 控制大小），只保留立方体范围内的点，超出范围的点通过 ikdtree.Delete_Point_Boxes() 批量删除。这种「局部地图 + 增量 KDTree」的组合，既减少了 KDTree 中的总点数，又避免了全局地图的冗余计算，进一步提升速度。
  3. 并行化搜索（可选）代码中使用了 #pragma omp parallel for 指令，支持多线程并行搜索多个点的近邻（如 h_share_model 函数中对所有特征点的近邻搜索），充分利用多核 CPU 算力。

*iVox - PHC

  1. 查询点预处理

    给定查询点 $p$（当前帧的激光点），先根据 $p$ 和大体素尺寸 $l_v$，找到它所属的大体素。再在大体素内部，根据 $p$ 的相对位置和 $K$，找到它对应的小空间单元 $x$。

  2. 三维 -> 一维

    调用 $H^{−1}(x)$，把三维小单元 $x$ 转成一维索引 $t$，这是查询点在 PHC 曲线上的「位置锚点」。

  3. 确定一维搜索范围

    在三维空间中，找距离点 $p$ 不超过 $r_s$(三维搜索半径) 的 k 个近邻。

    需要先把三维搜索半径$r_s$，转换成「一维上要搜索的单元数 $\rho$」：

    • $\frac{2^K r_s}{l_v}$：把三维半径 $r_s$ 转换成「在大体素内部，跨越多少个子单元」的比例。
    • $ceil(log2(⋅))$：向上取整到 2 的幂次，保证覆盖 rs 的范围。
    • $exp(⋅)$：本质是 $2^x$（log2 的逆运算），把比例放大到下一个 2 的幂次，确保三维半径被完全覆盖。
    • 最后立方 + 乘 8：因为是三维空间，每个维度都要覆盖，8 是 PHC 固定的系数。

    在一维 PHC 上，要从 t 向前 / 向后各搜 ρ 个单元，才能保证覆盖三维中半径 rs 的所有可能邻居。

  4. 一维搜索

    最终搜索范围 = $min(k, \rho)$，在一维区间 $[t−min(k,\rho),\quad t+min(k,\rho)]$ 内遍历所有小单元
