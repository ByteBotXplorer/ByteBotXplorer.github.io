ROS基础概念

Created2026-03-14|Updated2026-03-16|ROS
|Word Count:2.4k|Reading Time:8mins|Post Views:

句柄

  • ros::NodeHandle nh;

    • 含义：创建了一个命名空间为全局（或相对于节点名）的节点句柄。
    • 用途：这个句柄通常用于发布话题、订阅话题、提供服务、调用服务以及操作参数服务器。
    • 命名空间：如果节点启动时指定了命名空间（例如 ns=my_ns），那么通过 nh 创建的话题或服务会自动带有该前缀（例如 /my_ns/chatter）。如果没有指定，则通常在全局命名空间下。

  • ros::NodeHandle private_nh("~");

    • 含义：创建了一个私有节点句柄。
    • 参数 "~"：这个波浪号符号在 ROS 中代表“私有命名空间”。
    • 命名空间：私有命名空间通常解析为 <node_name>。例如，如果你的节点名是 my_node，那么通过 private_nh 访问的资源路径通常是 /my_node/...，即通常解析为 /节点名/话题名。
    • 用途：这个句柄主要用于获取该节点特有的参数。

实现原理

在ROS底层实现中，NodeHandle是一个类，充当ROS节点与ROS主节点以及其他节点通信的入口点。

  • 构造与注册

    当创建一个NodeHandle对象时，会引用底层节点的实例。如果这是该节点创建的第一个句柄，它会触发节点与ROS Master的连接握手过程。

  • 命名空间解析

    • nh使用全局或相对命名空间。
    • private_nh在构造时接收~，内部逻辑会将后续的操作名称前缀加上当前节点的名称。

  • 资源管理

    NodeHandle 管理着发布者、订阅者、服务等的生命周期。当 NodeHandle 对象被销毁（例如离开作用域）时，它通常会自动注销由它创建的所有发布者、订阅者等资源。

用途

用于区分“全局/公共资源”和“私有/局部配置”。

  • nh (公共句柄)：
    • 用于节点之间的数据传输。
    • 例如：订阅激光雷达数据 (/scan)，发布速度控制指令 (/cmd_vel)。
  • private_nh (私有句柄)：
    • 用于读取 Launch 文件 中为该特定节点配置的参数。
    • 例如：读取机器人的轮距、最大速度、PID 参数等。

从参数服务器中读取参数

  1. 调用对象：private_nh
    • 这是一个 ros::NodeHandle 类的对象（通常是一个私有句柄）。
    • 它表示我们要在这个句柄对应的命名空间（通常是节点自己的私有命名空间，如 /move_base）下查找参数。
  2. 函数名：.param
    • 这是 NodeHandle 类的一个成员函数模板。
    • 它的作用是：尝试读取参数，如果读取失败（参数不存在），则使用默认值。
  3. 参数列表（三个参数）：
    • 参数 1："base_global_planner"
      • 类型：std::string（字符串字面量自动转换）。
      • 含义：参数名（Key）。告诉 ROS 去参数服务器里找叫这个名字的参数。
    • 参数 2：global_planner
      • 类型：引用（Reference）。
      • 含义：存储变量（Output Parameter）。
      • 作用：这是一个输出参数。如果参数服务器里找到了对应的值，这个值会被赋值给 global_planner 变量。
    • 参数 3：std::string("navfn/NavfnROS")
      • 类型：std::string。
      • 含义：默认值（Default Value）。
      • 作用：如果参数服务器里没有找到 "base_global_planner" 这个参数，那么 global_planner 就会被赋值为 "navfn/NavfnROS"。

通信连接

advertise

  1. vel_pub_ (左值)

    • 含义：这是一个成员变量名。

    • 类型：它的类型是 ros::Publisher。

    • 作用：这个变量用来保存创建好的发布者对象的“句柄”。后续如果想发布速度消息，必须使用这个变量（例如 vel_pub_.publish(msg)）。

  2. nh.advertise<...>(...) (函数调用)

    • nh：是 ros::NodeHandle 类的对象，代表节点与 ROS 系统的连接接口。
    • .advertise：这是 NodeHandle 类的一个成员函数模板。它的作用是告诉 ROS Master：“我要在这个话题上发布消息，请帮我建立连接。”

  3. <geometry_msgs::Twist> (模板参数)

    • 含义：这是指定发布消息的数据类型。
    • 语法：尖括号 <> 是 C++ 模板的语法。
    • 内容：geometry_msgs::Twist 是 ROS 中定义的一种消息类型，专门用于表示机器人的速度（包含线速度 x, y, z 和角速度 x, y, z）。
    • 作用：它告诉 advertise 函数，我们将来要通过这个发布者发送的数据结构是 geometry_msgs::Twist 格式的。这确保了类型安全——如果试图发送 LaserScan 类型的数据，编译器会报错。

  4. ("cmd_vel", 1) (函数参数)

    这是传给 advertise 函数的两个实际参数：

    1. "cmd_vel"：
      • 类型：std::string。
      • 含义：话题名称。
      • 作用：发布者会在名为 /cmd_vel（或相对于命名空间的 cmd_vel）的话题上广播消息。订阅者（如底层驱动节点）必须订阅同样名称的话题才能收到数据。
    2. 1：
      • 类型：unsigned int (无符号整数)。
      • 含义：消息队列长度。
      • 作用：如果发布消息的速度很快，而接收或处理的速度很慢，消息就会在缓冲区中堆积。这个参数指定了缓冲区最多能存多少条消息。
      • 为什么是 1？：对于控制指令（如 cmd_vel），我们通常只关心最新的指令。旧的指令（比如 0.1 秒前的速度）如果还没发出去，就已经过时了，直接丢弃即可。所以设置得比较小（通常是 1），可以保证机器人响应的实时性，避免延迟。

subscribe

  1. goal_sub_ (左值)

    • 类型：ros::Subscriber。

    • 含义：这是一个成员变量。

    • 作用：保存订阅者的句柄。只要 goal_sub_ 存在（没有被销毁），ROS 就会一直保持对 "goal" 话题的订阅。如果 goal_sub_ 被销毁，订阅就会自动断开。

  2. simple_nh.subscribe<...>(...) (函数调用)

    • simple_nh：节点句柄 (NodeHandle)。

    • .subscribe：成员函数，用于订阅话题。

    • <geometry_msgs::PoseStamped>：模板参数。

      • 指定订阅的消息类型。这里表示只关心 geometry_msgs::PoseStamped 类型的消息。

  3. "goal" 和 1 (函数参数)

    这是传给 subscribe 函数的前两个参数：

    1. "goal"：话题名称。我们要监听这个名字的话题。
    2. 1：队列大小。如果接收消息的速度快于处理速度，缓冲区最多存 1 条消息（新的会覆盖旧的）。

  4. [this](auto& goal){ goalCB(goal); } (回调函数 - 重点)

    1. [this] (捕获子句)：
      • 含义：让 Lambda 表达式能够访问当前类的成员。
      • 作用：因为我们在 Lambda 内部调用了 goalCB，这是当前类的成员函数。如果不捕获 this，Lambda 就不知道 goalCB 是谁，编译会报错。
    2. (auto& goal) (参数列表)：
      • goal：从话题接收到的消息对象。
      • auto：自动类型推导。编译器会自动把它推导为 const boost::shared_ptr<const geometry_msgs::PoseStamped>&。
      • &：引用传递，避免拷贝数据，提高效率。
    3. { goalCB(goal); } (函数体)：
      • 含义：具体的逻辑。
      • 作用：它只是一个“二传手”。当收到消息 goal 时，它不做处理，直接把消息转发给当前类的成员函数 goalCB 去处理。

ROS插件系统

ROS 插件系统（主要基于 pluginlib）是一种用于在运行时动态加载或卸载软件模块的机制。它允许开发者编写符合特定接口的代码，并将其编译成独立的库，而不需要修改主程序的源代码。

概念：解耦与扩展

插件系统的核心目的是将接口定义与具体实现分离。

  • 主程序：只定义接口（基类），不关心具体算法是谁写的，也不关心具体算法是怎么实现的。
  • 插件：实现了主程序定义的接口，包含具体的算法逻辑。

工作原理

四要素：

  1. 插件类（C++ 代码）

    • 开发者编写一个 C++ 类，继承自主程序定义的基类（例如 nav_core::BaseGlobalPlanner）。
    • 必须实现基类中定义的所有纯虚函数（如 makePlan, initialize）。

  2. 插件导出宏（C++ 代码）

    • 在插件的 .cpp 文件中，必须使用特殊的宏将这个类注册到插件系统中。
    • 例如：PLUGINLIB_EXPORT_CLASS(MyPlanner, nav_core::BaseGlobalPlanner)
    • 这个宏的作用是告诉编译器：把这个类的信息导出，让 pluginlib 能在运行时找到它。

  3. 插件描述文件（XML）

    • 一个 XML 文件（通常命名为 pluginlib.xml），它充当了“注册表”的角色。

    • 它描述了插件的名字、类型、基类类型以及所在的库文件名。

运行流程

  1. 读取参数：从参数服务器读取字符串（如 "dwa_local_planner/DWAPlannerROS"）。
  2. 查找索引：pluginlib 在 ROS 系统中查找哪个包的 XML 文件里注册了这个名字。
  3. 定位库文件：找到对应的动态链接库（.so 文件）。
  4. 动态加载：操作系统将该库加载到内存中。
  5. 实例化：调用库中的类工厂，创建对象，并返回指向基类的指针。
