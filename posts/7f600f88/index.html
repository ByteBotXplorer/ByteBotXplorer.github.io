编译型语言与解释型语言

Created2026-02-09|Updated2026-02-10|编程
|Word Count:1.4k|Reading Time:4mins|Post Views:

进程

进程是“运行中的程序”，可执行文件/脚本是静态的磁盘文件。

进程是操作系统分配资源（CPU、内存、PID）的基本单位，包含三大核心部分：

  • 代码段：存储CPU可执行的指令（机器码/字节码）；
  • 数据段：存储全局变量、静态数据等；
  • 栈/堆：存储局部变量、动态分配的内存（如Python的对象、C++的new对象）。
graph TD
	A[用户执行命令] --> B[操作系统创建进程控制块（PCB）]
	B --> C[分配内存空间]
	C --> D[加载文件中的指令/数据到内存]
	D --> E[CPU调度执行进程指令]

C++编译出的 exe/a.out 是二进制可执行文件（存储机器码），但只有运行时才会被加载为进行；而Python的 .py 是文本脚本文件（存储源码），本身无执行能力，运行时只有Python解释器会被创建为进程。

编译型语言（C++）

执行逻辑的核心：提前编译为机器码，运行时直接加载为进程。

graph TD
	A[编写.cpp源码] --> B[编译器g++预处理/编译/汇编]
	B --> C[生成二进制可执行文件a.out/.exe]
	C --> D[执行可执行文件]
	D --> E[操作系统创建进程，加载机器码到代码段]
	E --> F[CPU直接执行代码段的机器指令]
	F --> G[进程结束，释放资源]
  • 编译阶段：编译器将人类可读的C++代码，翻译成与CPU架构（x86/ARM）匹配的机器码（二进制指令），并封装为可执行文件，该文件包含：代码段：机器指令；数据段：初始化的全局变量；符号表：调试信息（可通过strip命令去除）。
  • 运行阶段：操作系统直接将可执行文件的内容加载到新进程的内存中，CPU 无需中间层，直接执行代码段的机器指令。

解释型语言（Python）

行逻辑的核心是 “解释器作为进程主体，脚本仅作为输入数据“。

graph TD
A[编写.py源码] --> B[执行: python test.py]
B --> C[操作系统创建Python解释器进程]
C --> D[解释器读取.py文本文件]
D --> E[解释器将源码编译为字节码（.pyc）]
E --> F[解释器执行字节码（调用系统API/机器指令）]
F --> G[进程结束，释放资源]

  • 解释器（核心）：python命令启动的是 Python 解释器（如python3.10可执行文件），操作系统为解释器创建进程，.py脚本只是这个进程的 “输入数据”，而非进程本身。

    CPython解释器：编译器+虚拟机

    编译器负责把 Python 源码翻译成字节码，虚拟机负责执行这些字节码。

    Python 源码 → [CPython 编译器] → 字节码 → [CPython 虚拟机] → 机器指令/系统调用

  • 字节码的中间层：解释器不会直接执行源码，而是先将源码编译为 Python 字节码（一种与平台无关的中间指令），存储在.pyc文件中（或内存中）。字节码不是机器码，需要解释器逐行解析，并调用操作系统的底层接口完成执行。

    Python 字节码：是 Python 源码编译后生成的、与平台无关的中间指令集，是 Python 虚拟机（PVM）能直接识别和执行的 “指令语言”。既不是人类可读的源码，也不是 CPU 能直接执行的机器码，而是专门给 Python 解释器用的 “中间语言”。

    编译把 .py 源码编译成 Python 字节码（bytecode），存储在 .pyc 文件或内存中，这个编译过程是自动、即时完成的，看不到显式的编译命令（如 g++）。Python 虚拟机（PVM）逐行解释执行这些字节码，将其转换为机器指令或调用系统 API 完成实际操作。

    • 当第一次运行.py文件时，Python 解释器会把编译好的字节码缓存到__pycache__目录下的.pyc文件中（文件名如test.cpython-310.pyc，后缀包含 Python 版本）；

    • 下次运行时，如果源码没有修改，解释器会直接加载.pyc中的字节码，跳过重新编译的步骤，提升执行效率；

    • .pyc文件是字节码的二进制存储形式，直接打开是乱码，但可以通过工具反编译回字节码指令。

  • 脚本与进程的关系：

    • .py脚本的文本内容会被读取到解释器进程的内存中（属于数据段），但并非进程的核心执行指令；
    • 脚本执行过程中生成的变量、对象（如list、dict），才是进程栈 / 堆的核心数据；
    • 整个过程中只有 “解释器进程”，脚本本身不会成为进程。
维度 编译型语言（C++） 解释型语言（Python）
核心执行单元 可执行文件运行后生成的独立进程 Python 解释器进程（脚本为输入）
指令类型 直接执行 CPU 可识别的机器码 解释器解析字节码，再调用机器码
内存加载内容 机器码 + 静态数据直接加载到进程内存 解释器代码 + 脚本字节码 + 运行时数据
效率 高（无中间解析环节） 低（多一层解释器解析）
跨平台性 差（机器码与 CPU 架构绑定） 好（字节码与解释器绑定，解释器跨平台）
