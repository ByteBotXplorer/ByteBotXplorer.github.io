Catkin

catkin是ROS的构建系统、工具集（类似于 Linux 下的 Make，Java 的 Maven，或者 Python 的 setuptools）。

名字来源于一种多刺的家猫尾巴上的毛丛（Kinkajou 的尾巴），寓意是“像编织一样把很多包组合在一起”。

  • 是基于标准的CMake构建出来的，是对标准CMake构建系统的一层封装和扩展。增加了一些针对Python、消息定义和服务定义的自动化处理逻辑。
  • 当在终端输入catkin_make或colcon build时，就是在调用这套构建系统
  • 目的：解决ROS开发中的特殊需求，比如自动处理.msg和srv文件的生成、Python脚本的安装、复杂的包依赖管理。
  • 工作：找到所有的包，按正确的顺序编译，然后将结果放到devel和install文件夹中。

Catkin核心组成

CMake宏

  • 在 CMakeLists.txt 里看到的 catkin_package、add_message_files、generate_messages 等命令。
  • 这些宏定义在 /opt/ros/<ros_distro>/share/catkin/cmake/toplevel.cmake 等文件中
  • 扩展了标准 CMake 的功能，让 CMake 能“听懂” ROS 的术语

Python脚本

  • 用于处理一些CMake不擅长的逻辑，比如查找python包、解析package.xml等

构建工具

  • 一些终端命令

CMakeLists.txt 是 CMake 的标准配置文件。

在 ROS 中，每个功能包都有一个。

  • 文本文件，里面写满了“命令”
  • 其中的命令告诉构建系统：我的源码在哪里？我依赖哪些库？我要生成什么可执行文件？

功能包 CMakeLists.txt(src/包名/ 下)

find_package

find_package 命令去系统中查找 catkin 以及 roscpp、std_msgs 等组件。查找catkin编译系统（ROS专用编译工具），并列出本包需要依赖的所有ROS功能包。

找到后，CMake 会自动定义（或填充）几个关键的变量，其中就包括：

  • ${catkin_LIBRARIES}：包含所有找到的组件对应的库文件路径（例如 /opt/ros/noetic/lib/libroscpp.so 等）。
  • ${catkin_INCLUDE_DIRS}：包含所有找到的组件的头文件路径。

${catkin_LIBRARIES}

是一个列表变量，里面存放的是绝对路径。

主要用途是链接。当你编写完 C++ 代码，想要编译成一个可执行文件或库文件时，你需要告诉编译器：“请把 ROS 的核心库链接到我的程序里，否则我的程序运行不起来”。

generate_dynamic_reconfigure_options

generate_dynamic_reconfigure_options 是 ROS 的 dynamic_reconfigure 包提供的一个 CMake 宏。它的核心任务是在编译过程中处理 .cfg 文件。

执行过程

  • generate_dynamic_reconfigure_options(cfg/MoveBase.cfg)

当运行 catkin_make 或 colcon build 编译项目时，这段代码会执行以下操作：

  1. 调用 Python 解释器去运行 cfg/MoveBase.cfg。
  2. 该脚本会利用 dynamic_reconfigure 提供的库，生成一系列中间文件（通常是 .cpp 和 .py 文件）。
  3. 这些生成的文件会被放置在构建目录（如 devel 或 build 文件夹）中，使得你的 C++ 节点或 Python 节点可以包含或导入这些定义。

应用场景

用于动态参数服务器。

  • 传统方式：如果你修改了 ROS 节点（launch文件）的参数（例如 PID 控制器的 P、I、D 值），通常需要重启roslaunch节点才能生效。
  • 使用 dynamic_reconfigure：通过这段代码生成的配置，你可以在节点运行时，使用 rqt_reconfigure 图形化界面或者命令行工具实时修改参数（在 cfg/MoveBase.cfg 中定义了的参数），节点会立即收到更新并应用，无需重启。

catkin_package

是 catkin CMake 构建系统提供的一个宏，专门用于配置包的导出信息。它通常放在 CMakeLists.txt 中 add_library 或 add_executable 之后，但在 catkin_add_nosetests 之前。

实现原理：当构建该包时，catkin_package 会生成特定于该包的 CMake 配置文件（如 <package_name>-config.cmake）。这些文件会被安装到 ROS 的工作空间或安装目录中。当其他包使用 find_package(catkin REQUIRED COMPONENTS <current_package>) 时，CMake 会读取这些配置文件，从而获取该包的头文件路径、库文件路径以及它所依赖的其他包信息。

include_directories

指定编译时的头文件搜索目录。

  • include_directories(${catkin_INCLUDE_DIRS})：用find_package找到的路径，告诉编译器去哪找头文件

target_link_libraries（链接库）

告诉链接器，生成当前目标（可执行文件或库）时，需要用到哪些库文件（.so 或 .a）。

add_dependencies（构建顺序依赖）

告诉 CMake，在构建当前目标之前，必须先构建完另一个目标。

用于定义顶层目标之间的依赖关系。语法为 add_dependencies(target-name depend-target1 depend-target2 ...)。

  • target-name:被依赖的目标（即主目标）。它通常是通过 add_executable(target-name ...) 或 add_library(target-name ...) 定义的。

  • ${${PROJECT_NAME}_EXPORTED_TARGETS}:

    • 这是一个嵌套变量引用。
    • 假设 PROJECT_NAME 是 my_pkg，CMake 首先将其展开为 ${my_pkg_EXPORTED_TARGETS}。
    • 然后，CMake 会查找名为 my_pkg_EXPORTED_TARGETS 的变量。这个变量通常由 ROS 的 catkin 机制自动维护，包含了当前包中导出的、且其他包可能需要依赖的目标（例如：生成的消息头文件、服务定义、动态重配置配置文件等）。
  • ${catkin_EXPORTED_TARGETS}:
    • 这是 catkin 构建系统定义的一个全局变量。
    • 它包含了当前包所依赖的其他 catkin 包中导出的目标（例如：如果当前包依赖 roscpp 和 std_msgs，这些包生成的消息头文件目标就会包含在这里）。

顶层 CMakeLists.txt(工作空间根目录下)

execute_process

作用：在 CMake 配置阶段，在后台运行一条 shell 命令，并把命令的运行结果（成功与否、屏幕输出内容）捕获到 CMake 的变量中，而不是直接打印到终端屏幕上。

使用 execute_process，CMake会在后台静默运行catkin_find_pkg catkin ${CMAKE_SOURCE_DIR}，屏幕不会显示结果，变量_out会存储。

Catkin——构建工具

catkin_make

是对“CMake+Make”的封装，代替标准的CMake构建流程（对每个功能包进行），即：

catkin_make可以并行处理整个工作空间，自动处理功能包的依赖顺序，一次性把所有功能包编译好。

工作流程

  1. 检查环境

    读取 ROS_PACKAGE_PATH，确保它能找到你的工作空间。

  2. 扫描工作空间

    查找 src 文件夹下所有的包（每个包里都有 package.xml 和 CMakeLists.txt）

  3. 构建拓扑图

    分析包之间的依赖关系（比如 A 包依赖 B 包），决定先编译谁

  4. 调用 CMake

    在 build 文件夹中运行CMake，读取每个包的 CMakeLists.txt，在build/目录下生成 Makefile。

    CMake：

    读取CMakeLists.txt，然后生成一个底层的构建文件（通常是 Unix 下的 Makefile，或者是 Windows 下的 Visual Studio 解决方案文件）。

    作用是跨平台，根据当前的操作系统生成对应的“本地构建规则”

  5. 调用 Make

    根据生成的 Makefile 进行实际编译

    Make：
    是一个构建工具。

    读取 CMake 生成的 Makefile，根据里面定义的规则（比如：main.cpp 依赖 main.h，如果 main.h 变了就要重新编译 main.cpp），去调用编译器（g++ 或 clang）进行实际的编译和链接工作

  6. 设置环境

    把生成的库文件、可执行文件、Python 脚本等“安装”到 devel 文件夹（或者 install 文件夹）中，并生成 setup 文件

常用参数

  • catkin_make -DCATKIN_WHITELIST_PACKAGES="package1;package2"
    • 只编译指定的包。这在调试时非常有用，可以节省大量时间。
  • catkin_make install
    • 编译完成后，将结果安装到 install 文件夹。这是为了部署到机器人上时使用的（类似于 Linux 的 make install）。

工作空间的目录结构

  • build/：这是 catkin_make 的“临时办公室”。所有的计算、依赖分析都在这里进行。如果编译出错了，有时候删除这个文件夹重新编译（rm -rf build && catkin_make）能解决奇怪的问题。
  • devel/：这是“成品仓库”。
    • 编译好的节点（比如 talker）在 devel/lib/<package_name>/ 下。
    • setup.bash：这是最重要的文件。每次打开新终端运行 ROS 程序前，必须执行 source devel/setup.bash。这行命令的作用是把 devel/lib 加入到系统的 PATH 环境变量中，这样系统才能找到你编译好的 talker 节点。
  • src/：这是作为开发者唯一需要关心的目录，代码都在这里。

catkin 包

即空座空间下的功能包，是 ROS 中组织代码的基本单元。

组成：

  • 源代码（节点）
  • 配置文件（launch文件、msg/srv 定义）
  • 依赖描述（package.xml）
  • 构建脚本（CMakeLists.txt）
